def merge_sort(nums):
    if len(nums) <= 1:
        return nums

    middle = len(nums) // 2
    left = merge_sort(nums[:middle])
    right = merge_sort(nums[middle:])

    result = []
    i = 0
    j = 0

    while i < len(left) and j < len(right):
        if left[i] < right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    result += left[i:]
    result += right[j:]

    return result

Consider the two functions duplicate_exists0 and duplicate_exists1 defined below. Both of these functions correctly
determine if an integer array g contains duplicate elements (in other words, if there exists a number in g that can be
found more than once). Note that duplicate_exists1 uses the syntax "if x in seen," which is the condition when an

def duplicate_exists0(g):
    i = 0

    while i < len(g):
        j = i + 1

        while j < len(g):
            if g[i] == g[j]:
                return True
                
            j = j + 1

        i = i + 1

    return False

def duplicate_exists1(g):
    seen = []
    
    for x in g:
        if x in seen:
            return True
            
        seen.append(x)
        
    return False
    
Determine, with explanation, the worst-case time complexities of the two functions above. Note that n = len(g).

Possible solution:
=======================
"""

# Solution for first programming question

# This helper function determines if num (a number) is in g, which is an integer array.

def search(g, num):
    for val in g:
        if val == num:
            return True
        
    return False

def help_monks(n, holes):
    # Taking care of the base cases (only 1 step, only 1 step and it has a hole, or step n has a hole)
        
    if n == 1:
        if search(holes, 1) == True:
            return 0
        
        elif search(holes, 1) == False:
            return 1
    
    elif search(holes, n) == True:
        return 0
    
    else:
        num_ways = 0
        
        # If the monks end their journey through the tower by taking one step, they must have traveled
        # successfully from step (n - 1) to step n. This requires step (n - 1) to not be a hole. Since
        # their last step is fixed, the total number of ways they could have went from step 1 to step n
        # is equal to the number of ways they could have went from step 1 to step (n - 1). For this to
        # occur, the tower must have at least 2 steps (n >= 2), but the base case already forces this.
        
        if search(holes, n - 1) == False:
            num_ways = num_ways + help_monks(n - 1, holes)
        
        # If the monks end their journey through the tower by taking two steps, they must have traveled
        # successfully from step (n - 2) to step n. This requires not only step (n - 2) to not be a hole,
        # but step (n - 1) cannot be a hole also because monks cannot step over holes. Since the last two
        # steps are fixed, if these conditions are met, the total number of ways they could have went from
        # step 1 to step n is equal to the number of ways they could have went from step 1 to step (n - 2).
        # For this to occur, the tower must have had at least 3 steps, so we also need to check n >= 3 (the
        # only thing guaranteed by passing the base case is n >= 2).
        
        if n >= 3 and search(holes, n - 2) == False and search(holes, n - 1) == False:
            num_ways = num_ways + help_monks(n - 2, holes)
            
    return num_ways
    
# Solution to second question

# Both of the solutions provided have an O(n^2) time complexity. duplicate_exists0 uses a nested loop; the
# outer loop requires n operations, where n = len(g), and each iteration of the outer loop iterates over the
# inner loop to a maximum of n times as well. This is what gives the first solution O(n^2) time complexity.
# duplicate_exists1 stores a list called seen, and determines if a new element is already inside any elements
# that are in seen (have been seen already). The outer for loop requires n operations, and "if x in seen"
# requires a linear search (O(n)) through the seen list that requires a maximum of n operations. This is what
# gives the second solution O(n^2) time complexity.

        return
